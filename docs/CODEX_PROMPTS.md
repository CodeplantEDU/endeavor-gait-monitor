# Codex에 붙여 넣는 작업 프롬프트

먼저 저장소를 내려받고 Codex에서 **저장소 루트 폴더**를 엽니다. 아래 코드 블록 중 원하는 작업 하나를 복사해 대화창에 붙여 넣습니다. `[대괄호]` 부분은 실제 필요한 값으로 바꾸세요. API 키와 운영 이용 코드는 프롬프트에 넣지 않습니다.

작업이 끝나면 Codex가 알려주는 실제 실행 주소와 검사 결과를 확인하세요. 생성된 코드·테스트 통과만으로 실제 센서 또는 의료 성능이 검증됐다고 해석하지 않습니다.

## 1 처음 내려받은 프로젝트 실행

```text
이 저장소의 README.md, AGENTS.md, docs/ARCHITECTURE.md를 읽어 줘.
Node.js 24와 Python 3.10 이상이 있는지 확인하고 npm ci를 실행해 줘.
펌웨어는 유지하고 npm test, npm run test:python, npm run build를 실행해 줘.
비밀 값은 출력하지 말고 .env.local의 환경변수 존재 여부만 확인해 줘.
AI 키가 없으면 키를 요구하며 멈추기 전에 CSV 정제·그래프가 동작하는지 먼저 확인해 줘.
OpenAI 설정은 기존 키 재사용 또는 새 키 중 내 선택을 확인하고 진행해 줘.
npm run dev로 개발 서버를 열고 http://127.0.0.1:8774/#analysis를 보여 줘.
examples/sensor_example.csv로 파일 불러오기·그래프·정제 요약을 확인해 줘.
실제로 실행한 검사와 확인하지 못한 하드웨어 조건을 구분해서 알려 줘.
```

## 2 OpenAI CSV 리포트 연결

```text
이 프로젝트의 CSV AI 분석을 내 OpenAI 계정으로 연결해 줘.
모델은 gpt-6.1-terra를 유지하고 사용할 수 없다고 임의로 다른 모델로 바꾸지 마.
기존 OPENAI_API_KEY가 있는지 값은 출력하지 않고 확인한 뒤 재사용 또는 새 키 설정을 물어봐 줘.
키는 .env.local 또는 선택한 배포 환경의 서버 변수에만 저장해 줘.
EARLYBIRD_AI_ACCESS_CODE는 API 키와 다른 본인용 코드로 설정해 줘.
웹에서 센서 CSV·통계·질문이 OpenAI에 전송된다는 안내와 동의를 유지해 줘.
원시 가속도·각속도·질병 확률을 만들어 내거나 주기 10회·기준선 3회를 필수 조건으로 요구하지 마.
내 승인을 받은 후 합성 예시 CSV로 실제 API 호출을 1회 시험하고,
리포트 저장·새로고침 후 열람을 확인해 줘. 시험에는 실제 개인정보를 사용하지 마.
```

## 3 양발 ESP32 연결과 점검

```text
README의 센서 배선과 firmware/fsr_mpu_ble 소스를 확인해 줘.
앞 FSR GPIO35, 뒤 FSR GPIO34, MPU SDA21/SCL22 설정을 유지해 줘.
펌웨어를 수정하거나 업로드하지 말고 먼저 웹에서 양발 장치 등록과 수신 상태를 점검해 줘.
장치 이름이 같으므로 왼발·오른발을 임의로 추정하지 말고 실제 장치와 대응을 확인해 줘.
실측 데이터가 들어오지 않으면 합성 테스트를 실제 연결 성공이라고 보고하지 마.
캘리브레이션은 발마다 무부하 4초와 가압 정지 4초로 안내해 줘.
```

별도로 펌웨어 업로드를 원할 때만 다음 요청을 추가합니다.

```text
기존 INO와 OrientationFilter.h를 변경하지 않고 [대상 보드]의 [실제 COM 포트]에 업로드해 줘.
포트와 보드를 확인한 후 업로드하고 115200 시리얼에서 I2C 주소와 WHO_AM_I를 확인해 줘.
MPU6500의 기대 ID는 0x70이며 I2C 주소와 장치 ID를 구분해 기록해 줘.
사용 가능한 도구·보드 패키지가 없으면 구체적인 미완료 조건을 알려 줘.
```

## 4 CSV가 불러와지지 않거나 좌우 차이가 큰 경우

```text
CSV 분석 오류를 고쳐 줘. 먼저 dist/csv-analysis.mjs, dist/csv-report-ui.mjs,
dist/research.mjs, api/ai-analyze.mjs와 관련 테스트를 읽어 줘.
내가 선택한 CSV는 로컬에서 먼저 검사하고, 외부 전송 승인 없이 임의 업로드하지 마.
열 이름·시간 단위·발 구분·빈칸·NaN·중복·역순·샘플 누락을 확인해 줘.
좌우 ADC 크기가 다르다는 이유만으로 병적 비대칭이나 체중 분포라고 판단하지 마.
데이터를 0으로 채우거나 정답처럼 보이도록 주기·측정값을 만들지 마.
원본을 유지하고 정제 전후 행 수와 제외 이유를 보여 줘.
가장 작은 재현 테스트를 만든 뒤 수정하고 CSV 브라우저 검사까지 실행해 줘.
```

## 5 반복 파형의 주기 검출 개선

```text
CSV 직접 AI 분석은 계속 사용할 수 있게 유지하면서 반복 파형 검출을 보조 기능으로 개선해 줘.
FSR이 0으로 내려가지 않는 오프셋 신호와 좌우 감도 차이를 재현하는 합성 테스트부터 만들어 줘.
개인별 신호 범위·잡음·피크 간격을 검토하되 데이터를 보고 임계값을 임의로 조정한 결과를
검증된 heel-strike, 질병 탐지 정확도 또는 임상 기준으로 표현하지 마.
검출한 이벤트를 원 파형 위에 표시하고 검출 실패·불확실성도 확인할 수 있게 해 줘.
주기가 부족해도 CSV AI 리포트 생성은 차단하지 마.
실제 측정 데이터의 정답 주석이 없으면 정확도를 확인했다고 말하지 마.
```

```text
현재 CSV 분석 결과로 보행 기록 보고서를 만들어 줘.
측정 구간·정제 내역·채널별 통계·시간 그래프·AI 관찰·해석 한계·다음 확인 사항을 담아 줘.

70대라는 조건만으로 실제 참여자 기록이나 질병 예측 성능을 꾸며내지 마.
보행 변화와 걷기 불편이 반복될 때 전문 의료진 상담을 고려할 조건을 정리해 줘.
파킨슨병 확률이나 치료·복약 지시는 제공하지 마.
저장된 보고서의 HTML·JSON·브라우저 인쇄/PDF가 일관된지 확인해 줘.
```

## 7 내 Vercel 프로젝트에 배포

```text
docs/DEPLOYMENT.md를 읽고 이 프로젝트를 내 Vercel 계정에 배포해 줘.
계정·팀·대상 프로젝트·운영/미리보기 환경을 먼저 확인하고 다른 프로젝트를 덮어쓰지 마.
기존 Codeplant 운영 프로젝트용 스크립트를 새 계정에 그대로 실행하지 마.
npm test, npm run test:python, npm run build, npm run check:public을 통과시켜 줘.
원본 폴더가 아니라 vercel_site만 배포하고 .env·데이터·보고서·백업은 올리지 마.
AI 설정은 내 승인된 서버 환경변수를 사용하고 실제 값을 출력하지 마.
새 운영 origin이 API 허용 목록에 들어가는지 확인해 줘.
배포 후 공개 URL의 CSV 업로드·그래프·저장 복원을 검사해 줘.
실제 API 검사는 내가 승인한 경우 합성 데이터로 수행하고, 검사 종류와 결과를 알려 줘.
```
